# Ledger issue 37 — V1-a Thai-aware TextSplitter

Ruling: segment with Intl.Segmenter("th") and mark boundaries with U+200B rather than adding a Thai word-break dependency — Node 22 ships full ICU so the stdlib already knows Thai word boundaries — if wrong, a deployment on a small-ICU Node build silently loses Thai segmentation and falls back to today's character split.
Ruling: route only text containing Thai codepoints through the word-aware engine, leaving every other document on the original engine and separator list — the English regression test compares against Langchain's own output, so pure-Latin corpora are byte-identical — if wrong, an unrelated corpus rechunks and its stored embeddings no longer line up with fresh ones.
Ruling: keep the marker as an extra separator ahead of the empty string rather than replacing the list — paragraph, line and space breaks still win over word breaks in mixed Thai/English text — if wrong, mixed documents break at Thai words before sentence ends and chunks read worse than before.
Ruling: strip every U+200B from emitted chunks, including any the source document already carried — a zero-width space is invisible formatting an embedder cannot use — if wrong, a document that used U+200B meaningfully loses that mark, which we judged worth it over emitting our own scaffolding.
Ruling: scope to Thai only although Lao, Khmer and Burmese have the same defect and the same one-line fix — no eval corpus exists to prove those locales improve — if wrong, those scripts keep the mid-word cutting until a corpus lands. Marked with a ponytail comment.
