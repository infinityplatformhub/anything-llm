# PR-3 ledger

Ruling: Store deterministic HMAC-SHA-256 digests as PostgreSQL BYTEA and index them uniquely — O(1) lookup plus pepper separation makes DB dump insufficient — if wrong, pepper compromise still requires forced rotation.
Ruling: Generate 32 random bytes with explicit `apw-key-` and `apw-brx-` prefixes — meets 256-bit entropy and credential dispatch convention — if wrong, clients depending on legacy prefixes require forced migration already mandated by plaintext removal.
Ruling: Store scope arrays as JSON text with temporary `["*"]` on every route — PR-4 owns exact route vocabulary while PR-3 establishes default-deny middleware — if wrong, wildcard transition window remains broader than final least privilege.
Ruling: Missing API_KEY_PEPPER throws synchronously after dotenv and before Express construction/listen — boot must fail closed without self-assignment — if wrong, tests and utility scripts importing models need an explicit test pepper.
Ruling: Authentication audit carries scoped key id and display prefix only — no bearer secret or digest crosses event seam — if wrong, operators lose forensic correlation without improving secrecy.
Ruling: Migration deletes both legacy key tables before dropping plaintext columns — forced rotation was approved because no customer compatibility is required — if wrong, every integration must provision new keys after release.
Ruling: Split general and browser key changes into consecutive migrations in one release — browser keys retain user ownership and need digest/prefix only, while general keys gain lifecycle/scope fields — if wrong, browser scopes require a later additive migration.
Ruling: Rollback is intentionally destructive: digest cannot reconstruct plaintext, so down means empty tables and reissue — forced rotation is explicit rather than fake reversibility — if wrong, rollback operators must communicate another rotation.
Ruling: `validApiKey(action)` is the only scope enforcement surface and throws during route registration when action is absent — separate middleware can be forgotten silently — if wrong, dynamic action selection needs a different explicit factory.
Ruling: PR-3 publishes raw `apiKeyContext` only and defers seam Actor construction to authorization ActorResolver — preserves immutable impersonation provenance at one boundary — if wrong, consumers cannot call authorization until T-2 lands, by design.
Ruling: Temporary wildcard scope count is an exact burn-down invariant (67) — every replacement must reduce expected count visibly until PR-4 reaches zero — if wrong, route additions require same-commit counter change.
Ruling: PR-4c must remove the database default `'["*"]'` from `api_keys.scopes` after all route scopes are explicit — otherwise inserts that omit scopes retain global access even when route wildcard count reaches zero — if wrong, direct DB/model inserts remain a hidden wildcard issuance path.
Ruling: PR-4c completion must query both `api_keys` and `browser_extension_api_keys` and prove zero rows contain `*` — call-site counter alone cannot prove issued credentials are least-privilege — if wrong, legacy wildcard keys bypass every explicit action assignment.
