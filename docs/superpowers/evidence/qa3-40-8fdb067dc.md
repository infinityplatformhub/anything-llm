## R-2 — the asynchronous-mount residual is narrower than the comment claims

The sweep snapshots `app._router.stack` synchronously and its comment says routes mounted after
that point "are outside this synchronous startup contract and remain residual risk". I drove a
route in through that window to see how far the risk actually reaches.

| id | probe | result |
|---|---|---|
| R2a | mount an **ungated** mutating route inside `setImmediate` | **2 failed** — the timing test (`mounted route snapshot stays stable through immediate timers`, diff naming `"path": "/late-ungated-probe"`) **and** the gate sweep, which listed `"POST /late-ungated-probe"` |
| R2b | mount the same route **synchronously** | **2 failed** — the gate sweep and the mount guard |

R2a is the informative one. The route was caught **twice**, including by the sweep whose comment
disclaims it — because Jest evaluates the module at file load and runs the test bodies afterward,
so a `setImmediate` mount has already landed by the time `routesAtAssertion` is taken. The
timing test catches it independently.

So the residual is real but smaller than stated: it covers a route mounted after the *test body*
runs (a timer longer than the suite's own startup, a promise chained on I/O), not one mounted
after *module load*. The comment is conservative in the safe direction, which is the right way to
be wrong, and I am not asking for a change — but the honest statement of the limit is narrower
than the file currently claims, and it is worth someone knowing that before treating it as an
open hole.
