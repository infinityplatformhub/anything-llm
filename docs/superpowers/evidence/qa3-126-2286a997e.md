## Why

`capabilityGate.test.jsx` imports `./WorkspaceGate` directly and mounts it with literal
props. No test in the repo imports `pages/Main/Home` or renders it:

```
grep -rn "WorkspaceGate" src  →  only Home/index.jsx and Home/capabilityGate.test.jsx
grep -rln "pages/Main/Home" src | grep test  →  (nothing)
```

So `Home`'s side of the contract — that it calls the gate, on **both** return paths, with
`canCreate={can("workspace.create")}`, and does not re-decide outside it — has **zero**
coverage. N6 is the sharpest form: `WorkspaceGate` can be dead code and the suite is green.

RF-3 makes this a **regression, not a pre-existing gap**. The `2286a997e^` suite had:

```js
const source = readFileSync(`${__dirname}/index.jsx`, "utf8");
expect(source).toContain('if (!workspace && user && (loading || !can("workspace.create")))');
```

with a comment naming exactly this risk (*"the failure mode of #115, where a test drove a
local helper and the production path went unguarded. This is the guard"*). That assertion
is deleted. Its ledger justification is *"render test ครอบแทนได้ทั้งหมด"* — the render
test covers the **component**, and the deleted check covered the **call site**. Different
claims; the second is now unheld. Before the change, N1 and N6 would have been caught
(the condition would no longer be verbatim in `index.jsx`, or would be present twice).

This is the pattern the extraction was supposed to remove — a decision that looks gated
and is not — reintroduced one level up.

## What would close it

A render test for `Home` is what the ledger says is impractical, and it is. Cheaper
options, either sufficient:

- Give `WorkspaceGate` a `data-testid`/marker and assert `Home`'s rendered tree contains
  exactly one, on both `workspace && threadSlug` and the default path (needs Home
  mountable — the objection stands).
- Keep a **call-site** assertion instead of the old condition transcription: assert
  `index.jsx` contains no second copy of the condition and that both `return` statements
  in the component go through `gate(`. Still a source assertion, but it holds the claim
  the render test cannot reach — the same reasoning the ledger already accepts for
  slice 2 (*"สไลซ์ 2 จะเก็บ assertion 'สอง call site ใช้ค่าเดียวกัน' ไว้เพราะ render
  test ของ gate ครอบไม่ถึง"*). The identical argument applies here and was dropped.

Note a source assertion is a text guard, not a behavioural one (the #40 t4 M3 finding).
It is still strictly better than nothing, which is the current state.
