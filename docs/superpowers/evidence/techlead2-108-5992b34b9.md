## (ก) N7b รอด — `hasPassword` only ยังไม่ถูกบังคับที่ฝั่ง client

มิวแทน: ถ้า response ของ `GET /mailer/settings` มี `password` ให้เอามาใส่ state → **เทสไม่แดง**

สาเหตุ: เทส `a stored password is never sent back to the page` mock response ด้วย
`settingsResponse({ hasPassword: true })` ซึ่ง**ไม่มี field `password` อยู่ในนั้น** เทสจึงยืนยันว่า
"เมื่อ server ไม่ส่ง password มา ช่องจะว่าง" ซึ่งเป็นจริงเสมอไม่ว่า client จะเขียนโค้ดอย่างไร

**เป็นช่องโหว่จริงหรือไม่ — ไม่ใช่วันนี้** เพราะฝั่ง server (`endpoints/mailer.js:62-73`) คืน
`hasPassword: Boolean(password)` และไม่เคยใส่ค่า password ลง response ซึ่งผมอ่านยืนยันแล้ว
และ #108 ไม่ได้แตะไฟล์นั้น · แต่ contract ข้อ "`hasPassword` only" ถูกถือโดย**ฝั่ง server เท่านั้น**
ไม่มีอะไรฝั่ง client ที่จะจับได้ถ้าวันหนึ่ง server เปลี่ยน

**ขอเพิ่ม (ไม่ block)**: เทสที่ mock response แบบ **hostile** — `settingsResponse({ hasPassword: true,
password: "leaked-secret" })` แล้ว assert ว่าช่องยังว่างและ `"leaked-secret"` ไม่อยู่ใน DOM
นั่นเปลี่ยนเทสจาก "server ไม่ส่งมา" เป็น "ต่อให้ส่งมาก็ไม่แสดง" ซึ่งคือสิ่งที่ contract อ้าง
รูปแบบเดียวกับ R2 ของ #114 (assert บน body ทั้งก้อน ไม่ใช่ field ที่รู้จัก)

## F-3 — contract ที่ผมยกว่าชนกัน ตอนนี้ตรงกันแล้ว

ตอน pre-read ผมยกว่า `configHash(settings, password)` ผูก hash กับ password ดังนั้น
"password never in DOM" กับ "save ต้องส่ง password เดิม" ชนกัน · โค้ดที่ landed ตอบข้อนี้:

| ข้ออ้าง | ตรวจอย่างไร | ผล |
|---|---|---|
| password อยู่ใน state เฉพาะ wizard | `const [password, setPassword] = useState("")` — state ธรรมดา หายเมื่อ unmount | **จริง** |
| ไม่ persist | ไม่มี `localStorage`/`sessionStorage` เขียน password (grep ทั้งไฟล์) + N7a แดงเมื่อเพิ่ม | **จริง** |
| ไม่ render จาก GET | `const { hasPassword, ...stored } = response.settings` — destructure ทิ้ง `hasPassword` และไม่เคยแตะ `password` | **จริง (แต่ไม่มีเทสบังคับ — §ก)** |
| ส่ง password ทั้งตอน test และตอน save | `Mailer.test(settings, password, testTo)` (:147) และ `Mailer.save(settings, password)` (:155) + เทส `it IS sent to both the test and the save — the hash binds it` | **จริง** |

**flow ที่แก้ปัญหา**: admin พิมพ์ password ครั้งเดียวใน wizard → ส่งไปกับ test → ส่งไปกับ save
ใน session เดียวกัน hash จึงตรง · ถ้ากลับมาหน้านี้ใหม่ ช่องว่างและ hint บอกว่า
*"A password is stored. It is never sent back to this page — retype it to change or re-test"*
คือยอมรับว่าต้องพิมพ์ใหม่ ไม่ใช่ซ่อนปัญหา — **ตรงกับที่ผมขอให้ตอบก่อนเขียนโค้ด**
