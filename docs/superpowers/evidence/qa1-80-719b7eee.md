## 3. Route lane — `user.manage` gate

Proven with a positive control on the **same route and same actor**:

```
inviter (holds invite.create, NOT user.manage) + email -> 403
   "Sending an invitation by email requires user management permission..."
inviter, no email (copy-link)                          -> 200, invite created
```

**Method note:** my first attempt used `setup_admin` as the no-`user.manage` actor and got
403 on *both* paths. That proved nothing — `setup_admin` does not hold `invite.create` at
all (measured: only `super_admin:org` does), so the request never reached the mail gate. I
created a role holding `invite.create` without `user.manage` so the copy-link control
returns 200 and the 403 can only come from the gate under test.
