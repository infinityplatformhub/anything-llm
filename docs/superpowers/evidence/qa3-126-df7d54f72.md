## P3 — residual, cosmetic, fails closed

Only line comments are stripped. A `/* … */` block comment containing the condition text
trips N1:

```
/* historical: !workspace && user && (loading || !can("workspace.create")) */
```
→ **exit 1**, `N1: the condition is not duplicated at the call site` fails, with the real
code correct.

This is a **false positive**, i.e. it fails closed: it can annoy a future editor, it
cannot let a defect through. The repo's convention in these files is `//`, so it is
unlikely to fire. Not worth another SHA on a `plain` issue; worth a line in
residual-risks so whoever hits it knows why. If it is ever tightened, strip block
comments too rather than loosening the pattern.

## Standing caveat

These four are **text guards, not behavioural ones** (the #40 t4 M3 finding): they prove
the source says the right thing, not that the rendered tree behaves. That is the correct
trade here — the claims are about the call site, which no render test can reach without
mounting the chat surface — and the ledger now says so in the file itself. The behavioural
half is held by the six render tests above.
