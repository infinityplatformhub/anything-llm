## 3. **The defect — F1's slice is unbounded**

```js
const block = source.slice(source.indexOf('path: "/settings/mobile-connections"'));
const routeEnd = block.indexOf("},\n      {");
const routeBlock = block.slice(0, routeEnd);
```

When that exact delimiter is absent, `indexOf` returns **-1** and `slice(0, -1)` yields
**the entire rest of the file minus one character** — not an empty block, not an error.
The assertion then reads every route below this one. Fired, not argued:

| # | setup | result |
|---|---|---|
| P-bound | route → `ManagerRoute` **and** delimiter broken | killed (a `ManagerRoute` remains in the widened slice, so the negative assertion still bites) |
| **P-bleed** | route **ungated** (`<MobileConnections />`), delimiter broken, `// AdminRoute Component={MobileConnections}` planted 60 lines below | **PASSES — exit 0, 6 passed** |
| **P-bound2** | route correct, delimiter intact, `// ManagerRoute` planted in the **next** route block | **PASSES — exit 0** (correct: the bound holds here) |
| P-fp | route correct, delimiter broken | passes (no false positive; 15 `ManagerRoute` uses exist but all are **above** this route) |

P-bleed is the one that matters: **an unguarded route, green.** Exactly what #84's
`source.slice(at).match(...)` did, and the reason PMO ordered that search bounded to one
route block.

Not live today — it needs the delimiter to change, which is a prettier reformat or a route
reorder away, and `awk` confirms **0** `ManagerRoute` occurrences below this route right
now, so the negative assertion happens to be safe. But the guard **fails open** on a
formatting change, silently, and the file's own comment claims it reads "the
`/settings/mobile-connections` entry".

**Fix (one line):** refuse the -1 case rather than slicing on it —
`expect(routeEnd).toBeGreaterThan(0)` before the slice, or bound with
`block.slice(0, routeEnd === -1 ? block.length : routeEnd)` **plus** an assertion that the
delimiter was found. Then re-fire P-bleed: it must go red.

costs nothing and matches the comment's claim about "the routes this protects".
