## Note on my own coverage

My mutant set did not catch this. A-c fired at the *migration's* grant half; G-h/G-i checked
drift on the three granted actions only. None asked whether a newly created action is in the
seed **vocabulary** — `super_admin`'s set is `ALL_ACTIONS`, so an action missing there is
granted to nobody on a fresh install, and a probe that always runs `migrate deploy` before
`seed.js` cannot see it. Standing rule added: when a migration creates an action, ask two
separate questions — who holds it, and is it in the vocabulary — because migrated and
freshly-seeded databases are different paths.
