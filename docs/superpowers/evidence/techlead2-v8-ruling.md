## ตรวจ premise — ถูกทั้งหมด และผมวัดเพิ่มสองข้อ

```
ไฟล์ที่อ้าง isMobile:  52   (ตรงกับ recon)
รูปแบบการใช้:  isMobile ?  58 · { isMobile } 51 · isMobile) 12 · !isMobile 5 · isMobile && 3
การกระจาย:     2 ครั้ง/ไฟล์ 37 ไฟล์ · 3 ครั้ง 10 · 4 ครั้ง 2 · 5 ครั้ง 2 · 9 ครั้ง 1
tailwind.config.js: ไม่มี screens override -> md = 768px จริง
```

**ข้อที่ผมวัดเพิ่ม 1 — ไม่มีการใช้ `isMobile` ที่ถามเรื่อง touch จริงเลยสักที่**

ผมกรองทุกบรรทัดที่ไม่ใช่ className/style/JSX ออกมาดู เหลือ 10 แห่ง และทั้งหมดเป็น
**การเลือก layout** (`if (isMobile) return <ต้นไม้อื่น>` หรือเปิด modal แทน panel) ·
ไม่มีที่ไหนถาม "อุปกรณ์นี้แตะได้ไหม" · **ข้อแนะนำของ recon ที่ว่า "คง `isMobile` ไว้เฉพาะที่
คำถามคือ touch จริง ๆ" ในทางปฏิบัติแปลว่า: ไม่ต้องคงไว้เลย**

**ข้อที่ผมวัดเพิ่ม 2 — มี `isMobileOnly` ปนอยู่หนึ่งแห่ง** (`ManageWorkspace/index.jsx:47`)
· คนละ predicate กับ `isMobile` (ตัดแท็บเล็ตออก) และ recon ไม่ได้พูดถึง · **แหล่งความจริง
ที่สามในไฟล์เดียว** ต้องอยู่ในสโคปการนับ ไม่งั้นจะเหลือค้างแบบไม่มีใครรู้

**ข้อที่ผมวัดเพิ่ม 3 — codebase มีแบบแผน hook สำหรับ media query อยู่แล้ว**:
`hooks/usePrefersDarkMode.js` ใช้ `window.matchMedia` ตรง ๆ · **แต่มันอ่านครั้งเดียวตอน
render ไม่ subscribe** ซึ่งเป็นบั๊กที่ V8 ต้องไม่ลอกไป — hook ของ V8 ต้อง
`addEventListener("change")` ไม่งั้นการหมุนจอ/ย่อหน้าต่างจะไม่ re-render

## (1) viewport หรือ user agent — **viewport เป็น authority เดียว**

**เห็นด้วยกับ recon และเหตุผลหนักกว่าที่เขียน**: ไม่ใช่แค่ "หน้าต่างแคบก็คือแคบ" แต่คือ
**UA ตอบคำถามผิดข้อ** · CSS ถาม "มีที่ว่างเท่าไร" · `react-device-detect` ตอบ
"อุปกรณ์นี้ยี่ห้ออะไร" · สองคำถามนี้ไม่มีความสัมพันธ์ที่รับประกันได้ และตารางของ recon
พิสูจน์ว่ามันขัดกันในสองทิศทาง

**สิ่งที่ทำให้ผมมั่นใจคือข้อที่ผมวัดเพิ่ม**: ถ้ามีสักที่ที่ถาม touch จริง ๆ การเก็บสอง
แหล่งไว้จะสมเหตุสมผล · แต่ทั้ง 10 แห่งเลือก layout · **ไม่มีอะไรให้เก็บ**

**ยอมรับว่ามันเปลี่ยนพฤติกรรมบนอุปกรณ์จริง และนั่นถูกต้อง**: แท็บเล็ตแนวนอน 900px
ควรได้ layout เดสก์ท็อป — มันมีที่ว่างพอ · ผู้ใช้ที่ย่อหน้าต่างเดสก์ท็อปเหลือ 500px
ควรได้ layout แคบ — มันไม่มีที่ว่าง · **ทั้งสองกรณีวันนี้ได้ผลตรงข้ามกับที่ควรได้**

**เงื่อนไข**:
- hook ใหม่ต้อง **subscribe** ไม่ใช่อ่านครั้งเดียว (ดูข้อที่ผมวัดเพิ่ม 3)
- ต้องใช้ **breakpoint เดียวกับ Tailwind** และอ่านจากที่เดียว — ถ้า hardcode 768
  ในโค้ด JS แล้ววันหนึ่งมีคนใส่ `screens` override ใน `tailwind.config.js` เราจะกลับมาที่
  ปัญหาเดิมทันที · **RED FIXTURE**: เทสที่แดงถ้าค่าใน JS กับใน Tailwind ไม่ตรงกัน
- **`isMobileOnly` ต้องถูกจัดการด้วย** ไม่ใช่ปล่อยไว้เพราะชื่อไม่ตรง grep

## (2) scope: สามพื้นผิว หรือ 52 ไฟล์ — **สามพื้นผิว + ถอน dependency ให้หมด**

เห็นด้วยกับ recon เรื่อง "สามพื้นผิว" แต่ **ไม่เห็นด้วยกับการปล่อยอีก 49 ไฟล์เป็น residual เฉย ๆ**

**เหตุผล**: ตราบใดที่ `react-device-detect` ยัง import อยู่ 52 ไฟล์ คนถัดไปที่เขียน
component ใหม่จะ copy แบบที่เห็น · residual ที่เป็นข้อความใน ledger ไม่หยุดสิ่งนั้น

**สั่ง**: V8 แปลงสามพื้นผิว **และ** เพิ่ม lint rule / เทสที่ห้าม import ใหม่จาก
`react-device-detect` โดยมี allowlist ของไฟล์ที่ยังไม่แปลง · **ราคาต่ำมาก** (หนึ่ง rule)
และมันเปลี่ยน residual จาก "ข้อความที่คนจะลืม" เป็น "รายการที่หดลงได้และวัดได้"

การกระจายทำให้ข้อนี้ถูก: **37 จาก 52 ไฟล์ใช้แค่ 2 ครั้ง** (import + ใช้จริงหนึ่งที่) ·
การแปลงแต่ละไฟล์ถูกมาก · สิ่งที่แพงคือการ**ตัดสินใจ**ว่าแต่ละที่ควรเป็น breakpoint ไหน
ซึ่งเป็นเหตุผลที่ไม่ทำทีเดียวจบ — ไม่ใช่เพราะโค้ดเยอะ

**ทีละ component ไม่ใช่ครั้งเดียว** — และแต่ละอันต้องมีภาพ before/after ที่ breakpoint
ทั้งสองฝั่ง ไม่ใช่แค่ "เทสผ่าน"

## (3) sequencing — **เห็นด้วยกับที่ PMO ตั้งไว้ #121 → #126 s2 → V8**

`SettingsSidebar/index.jsx` เป็นไฟล์เดียวกันทั้งสาม issue · #126 แยก gate ออกมาเป็น
component ที่ทดสอบได้ ซึ่งทำให้ V8 มีอะไรให้ restructure ที่ชัดกว่า · ลำดับกลับกัน
จะทำให้ #126 ต้องแยก gate ออกจากโครงที่ V8 เพิ่งเปลี่ยน

**เพิ่มเงื่อนไข**: V8 ต้องเริ่มจาก **ไฟล์ที่ไม่ชนกับใคร** ก่อน (`ChatContainer`,
`Sidebar`) แล้วค่อยแตะ `SettingsSidebar` เป็นชิ้นสุดท้าย · ถ้า #126 ช้า V8 จะไม่ถูก
บล็อกทั้งหมด

## a11y baseline #124 เป็น DoD — **เห็นด้วย และทำให้แข็งกว่านั้น**

recon วัดถูก: `SettingsSidebar` มี **0** `aria-label`/`aria-expanded` และปุ่มเมนูเป็น
icon-only · **ปุ่มแรกที่ผู้ใช้มือถือต้องกด ไม่มีชื่อเลย**

**สั่ง**: DoD ไม่ใช่แค่ "ควบคุมใหม่ต้องมีชื่อ" แต่ต้องเป็น **เทสที่แดงถ้าไม่มี** ·
`aria-expanded` บนตัวที่ toggle panel ด้วย — recon ชี้ว่า `Sidebar` มี label แต่ไม่มี
expanded state ซึ่งแปลว่า screen reader ไม่รู้ว่าเปิดหรือปิด

## mockup — เห็นด้วยว่าจำเป็น และข้อที่ recon ขอถูกต้อง

สิ่งที่ mockup ต้องแสดงคือ **การเปลี่ยนผ่าน** ไม่ใช่ภาพนิ่งสองภาพ เพราะปัญหาทั้งหมด
คือการเปลี่ยนผ่านไม่สอดคล้อง · เคสแท็บเล็ตแนวนอนสำคัญที่สุด — เป็นเคสที่พฤติกรรม
**จะเปลี่ยน** หลัง ruling นี้ และผู้ใช้จริงจะสังเกตเห็น

## สรุปสั่งการ

1. **viewport เป็น authority เดียว** · hook ต้อง subscribe · breakpoint อ่านจากที่เดียวกับ
   Tailwind พร้อมเทสที่แดงเมื่อไม่ตรง · `isMobileOnly` อยู่ในสโคป
2. **สามพื้นผิว + lint rule กัน import ใหม่ พร้อม allowlist** — residual ที่วัดได้
   ไม่ใช่ข้อความ
3. **ลำดับตามที่ PMO ตั้ง** · V8 เริ่มจากไฟล์ที่ไม่ชน แตะ `SettingsSidebar` ท้ายสุด
4. **a11y เป็นเทสที่แดงได้ ไม่ใช่ checklist** — ชื่อ + `aria-expanded`
5. mockup ต้องแสดงการเปลี่ยนผ่าน โดยเฉพาะแท็บเล็ตแนวนอน
