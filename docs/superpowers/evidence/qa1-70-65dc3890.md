## NIT-1 (non-blocking) — defect 3's test is a source grep, and the behaviour test is elsewhere

`updateSettingsReturns.test.js` closes defect 3 with:

```js
expect(handler).toContain('error || "Failed to update default system prompt."');
```

That is pinned to a spelling. `error ?? "…"`, a renamed local, or extracting the fallback
to a constant all leave the guard green while enforcing nothing — the same shape I raised
on slice 2's M8b.

The behaviour *is* correct (§1 proves the real text reaches the client at 500), and the
handler is reached over HTTP by no test in this change: the HTTP suite drives only the two
preference routes. One `expect(response.body.message).toBe(<the model's error>)` against
`/system/default-system-prompt` would replace the grep with the property itself.
