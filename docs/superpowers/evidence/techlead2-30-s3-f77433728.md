## S-22 — the ordering point I raised in the pre-review is implemented and tested

I flagged that `fillSourceWindow`'s loop pushes and then checks `sources.length >= nDocs`, so
an ACL check applied after that point would let denied citations consume backfill slots — the
S-17 failure (a denied row occupying a topN slot) in a new place, silent, and with the
shortfall itself acting as a signal about how many denied citations existed.

The check is inside the `validSources` filter, **first in the predicate chain**, and the
comment says why in both respects — wasted slots and the count-as-oracle. There is a test for
exactly this shape: three denied citations placed *before* three readable ones, `nDocs: 3`,
asserting a full window of readable citations rather than one three-quarters wasted.

`aclFilter` is required and throws when absent, matching `pinnedDocs` and `queryAuthorized`.

**The call-site sweep is the best test in this slice.** Rather than a hardcoded list of the
five sites, it walks the tree and brace-matches each `fillSourceWindow({` call. Its own
comment records that an earlier regex-terminated version *"silently found 2 of the 5 sites"* —
which is the failure this whole issue is about, caught in the guard itself and written down.

### The order mutation is equivalent, and the reason is worth recording

I moved the check out of the predicate and into the push loop (`if (!isRowAllowed(...))

## S-25 — the count helper, and the two rules it gets right before the obvious one

`scopedNamespaceCount` returns `null` for out-of-scope, and the route answers 404. That is
rule 2 (out-of-scope reads as absent, never as forbidden), and it is the `NON_DISCLOSING`
rule `requirePermission` already applies — a 403 confirms the workspace exists.

`scopedTotalVectors` gives the instance total only to an `orgWide` actor and otherwise sums
over the actor's own workspaces. The comment on `workspaceIds` is correct and worth noting:
it is already `ceiling(creator) ∩ binding(key)` because `buildDocumentFilter` runs
`narrowToKeyBinding`, so a key bound to a workspace its creator has no grant for intersects to
nothing — **no separate check is needed, and adding one would be a second definition of the
same rule.** That is the reasoning that has been missing elsewhere in this issue.

The amplification cap **throws** rather than returning a truncated number, and the comment
explains the withdrawn `partial: true` design: a response shape that varies with who is asking
is itself a signal about the caller, and a silently truncated count is a wrong number that
looks exactly like a right one.

`buildVectorSearchResponse` emits **no `message` key in any case**, so the two bodies are
byte-identical rather than merely similar — closing the oracle I measured on the earlier round
(`{results: [], message: "No embeddings found..."}` versus `{results: []}`).

### GAP — nothing asserts the store is untouched on a refusal

Rule 1 in the file says scope is checked **before** the vector store is consulted, because
otherwise the refusal and the not-found paths are distinguishable by timing even when their
bodies match. I moved the `namespaceCount` call above the scope check; 102/102 still pass. So
I measured what the mutation actually does:

```
out-of-scope result: null | vector store was queried: true
```

The returned value is unchanged — which is why every assertion still passes — but the
mutation reintroduces exactly the timing difference the comment forbids. The suite tests
*what comes back*, never *what was touched*.

Cheap to close, and the fixture already has the shape for it: `cardinalityScope.test.js`
passes a stub `VectorDb` whose `namespaceCount` is a plain async function. Give it a spy, and
assert `not.toHaveBeenCalled()` on the out-of-scope, match-none and unknown-slug paths. That
converts a documented rule into a checked one.

Not a blocker: the code is correct today, and the failure it prevents is a timing side channel
rather than a content leak.
