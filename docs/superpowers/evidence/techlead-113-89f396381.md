## NIT — the no-op ternary hides the fixture's load-bearing choice

`aclGroupWorld:452`:

```js
workspaceId: role.scope === "workspace" ? null : null,
```

Both arms are `null`, so the ternary does nothing but reads as though scope were being
handled. The `null` is not incidental — it is what makes the test work. `heldPermissionIds`
is called with `targetWorkspaceId: null` (`:172`), which matches only `workspace_id IS NULL`
grants, so a genuinely workspace-scoped `owner` grant would contribute **nothing** to `held`,
and the actor would be refused for holding an empty set rather than for lacking `role.grant`.
The test would be green under a `document.share` bar too, and the control it exists to be
would be silently vacuous.

Granting the workspace-scoped role org-wide is the right call — it is what gives the actor
`document.share` at the scope the guard reads. It just needs to say so:

```js
// Granted org-wide (workspace_id null) deliberately: heldPermissionIds reads org-wide
// only, so a workspace-scoped grant would contribute nothing and this control would
// pass for the wrong reason — refused for holding nothing, not for lacking role.grant.
workspaceId: null,
```

Test-clarity only; the behaviour is correct as written.
