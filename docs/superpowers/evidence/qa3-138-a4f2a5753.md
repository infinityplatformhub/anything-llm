## Where I was wrong — one line each, as asked

1. **"the seed path does not set `category` either" — WRONG.** The seed has always set it
   (`prisma/seed.js:34`, `category: cat(action)`); I inferred the seed was at fault from a
   migrate+seed database without ever running the seed alone, which is the exact
   "measure both paths separately" rule I had written into my own oracle two messages earlier.

2. **"exactly 1 row has `category=''`" — right, but I attributed it wrongly.** The empty
   value came from the *migration's* `INSERT` (no `category` column, `@default("")` filled
   it); the seed's `upsert` has `update: {}`, so it never corrected a row the migration had
   already created. Cause was migration-writes-first, not seed-omits.

3. **"`scope=any` is correct by luck"** — half right, and it hid the real gap. On the old SHA
   `scope` was `any` in **both** shapes, and on db-push+seed **`org.member` was `any` too**
   (below). Dev1 is right that `scope` on the seed-only shape was the actual defect; I saw
   the symptom and named the wrong column.

## The measurement that settles it — old SHA `9445a6716`, both shapes

```
migrate deploy + seed          db push + seed
 action     | cat | scope       action     | cat       | scope
 directory.sync |   | any       directory.sync | directory | any
 org.member     | org | org     org.member     | org       | any
```

Two different failures, which is why one shape alone misleads:
- **migrate+seed**: `category` empty (migration created the row first, seed's `update: {}` left it);
- **db push+seed**: `category` **correct** — proving the seed sets it — but `scope` wrong for
  `directory.sync` **and for `org.member`**, a pre-existing row the slice never touched.

My §8 addendum ran only the first shape and generalised from it. Dev1's "did not reproduce
on a real DB" is consistent with this: on his shape the category was fine.

## Fix SHA `a4f2a5753` — both shapes, verbatim

```
=== SHAPE A (migrate deploy + seed) ===      === SHAPE B (db push + seed) ===
 action         | category  | scope           action         | category  | scope
 directory.sync | directory | org             directory.sync | directory | org
 org.member     | org       | org             org.member     | org       | org
```

`ON CONFLICT ("action") DO UPDATE SET "category"='directory', "scope"='org'` is what closes
the migrate-first ordering — the row is corrected rather than left as created.

**Tuple set-equality across shapes**: 63 rows each, `(action|category|scope)` sorted →
**identical, zero diff**. **C-c**: `category=''` → 0 and `scope` null/empty → 0, in **both**
shapes.
