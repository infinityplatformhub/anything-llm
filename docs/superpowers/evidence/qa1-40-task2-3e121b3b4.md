## NIT-1 — nothing catches "every workspace capability is false"

M-E (`return [action, false]` for every action) survives 40/40.

The suite pins the key SET (`Object.keys(...) === WORKSPACE_CAPABILITIES`) and the value TYPE (`boolean`), and the only test asserting a specific value asserts `false` (impersonation). So an endpoint that answers all-false for every caller passes.

Fail-closed, so not a security finding: the UI hides affordances it should show and every route still re-decides. But it is the mirror of the trap that bit slice 2 twice — a positive control that exists in the fixture is not a positive control unless a test reads it. The probe above shows `chat.send` is `true` for the seeded member, so the assertion costs one line:

```js
expect(body.workspace.capabilities["chat.send"]).toBe(true);
```

in `a workspace the caller belongs to answers the workspace vocabulary`. That kills M-E and makes the impersonation test's `false` mean something by contrast.
