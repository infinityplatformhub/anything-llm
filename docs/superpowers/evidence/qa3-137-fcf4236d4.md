## 1. Baseline

```

```

Cause, confirmed in source: `ORG_CAPABILITIES` on this branch still has 7 entries —
`system.read`, `system.write` and `user.read` arrive with #121. The endpoint returns
`undefined` for keys it does not batch, so the assertion fails on `undefined`, not `false`.
**Dependency, as PMO stated, not a defect.** The test declares this in its own comment and
deliberately does not `skip` — correct: a skip is invisible in a green run.

**Consequence for the harness, and the reason I changed it mid-probe.** With a red
baseline, "exit code non-zero ⇒ KILLED" would score every mutant as killed including a real
survivor. The harness now diffs the set of failing test **names** against the baseline's;
a mutant is KILLED only if it fails something the baseline did not. That change is what
makes the results below meaningful.

## 5. G-g — idempotency, by row count not by absence of an error

Replayed the migration SQL against a database that had already applied it:

| table | before | after |
|---|---|---|
| `role_permissions` | 125 | **125** |
| `permissions` | 63 | **63** |
| `policy_versions` | 12 | 13 |

`ON CONFLICT DO NOTHING` holds on both grant tables. `policy_versions` gains a row, which
is correct — it is an append-only change log, and a replayed grant *is* a new version
event. Not a defect; noted so nobody reads the +1 as non-idempotence.
